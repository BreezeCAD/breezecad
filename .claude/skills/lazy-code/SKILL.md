# Экономный код

Цель — сделать задачу самым коротким надёжным изменением и не тратить токены зря.
Короткое изменение — не хуже по качеству: оно проверяется тестами так же строго.

## Код
- Сначала найди, что уже есть: `grep -rn` по `src/` и `tests/`. Похожая функция есть — вызови или
  расширь её, не пиши вторую.
- Правь точечно (Edit), файлы целиком не переписывай. Новый файл — только если без него никак.
- Не добавляй «на будущее»: никаких параметров, классов, обёрток и настроек, которые сейчас не нужны.
- Никакого рефакторинга попутно. Увидел, что плохо, — запиши одной строкой в отчёт, не чини.
- Комментарий — только «почему», одна-две строки. Пересказывать код не нужно.
- Тесты: один тест на поведение, через готовые помощники из `tests/Fixtures.h`.

## Чтение
- Большие файлы (`Model.cpp`, `SketchTools.cpp`, `Application.cpp`, `WORKLOG.md`) — только
  `grep -n` и куски по 40–80 строк.
- Один и тот же файл не перечитывай: после Edit содержимое уже известно.
- Вывод команд обрезай: `| tail -20`, `| grep -E 'error|FAIL'`.

## Проверка
- Сборка — инкрементальная. Сначала свой набор тестов (`-ts=…` / `-tc=…`), полный прогон — один раз
  перед коммитом (долгий — в фоне; его можно делить: `--first=1 --last=320` и `--first=321`).
- На ПК автора через MCP: картинки — `view_snapshot` с `width` 512–640 и `height` 384–480,
  скриншоты экрана — `scale` 0.4–0.5. Полное разрешение — только если мелочь не разглядеть.
  Где хватает чисел (`part_properties`, `part_measure`, `part_tree`), картинку не снимай.

## Отчёт
- Сделал логическую часть и тесты зелёные → сразу коммит и push в рабочую ветку, не копи.
- В ответе: что сделано, чем проверено, что осталось. Без пересказа кода и без повторов.
