# AGENTS.md — правила работы над BreezeCAD

Проект: BreezeCAD (github.com/BreezeCAD/breezecad) — бесплатная офлайн параметрическая САПР.
Стек: C++20, OpenCASCADE 7.8.1, Dear ImGui. Отвечай по-русски.

## Режим «дознаватель» (обязателен перед кодом)
Перед реализацией задачи выжми из автора (MikeVerx) максимально точное ТЗ. Задавай
короткие конкретные вопросы: ожидаемое поведение, граничные случаи, визуальный результат,
критерии приёмки. Пока ТЗ не сформулировано однозначно — код не пишем. Если вопросов
больше 3–4, оформи их списком одним сообщением, не дёргай по одному.

## Режим «ленивый код»
- Минимальный диф: решаем поставленное, без «заодно поправлю».
- Не рефактори соседний код, не меняй стиль, не переименовывай без запроса.
- Не добавляй абстракций «на вырост» — только то, что требует задача.
- Если видишь баг вне задачи — сообщи списком, не чини молча.

## Жёсткие правила репозитория (нарушать нельзя)
- В `next` и `main` сливает только автор. Работа — в своей ветке (`fix/*`, `feat/*`), PR в `next`.
- Модули с основой не сливаются никогда. `modules/mcp` не трогать.
- Каждый новый подключаемый модуль BreezeCAD создаётся в отдельном репозитории `BreezeCAD/bz-module-<id>` из шаблона `BreezeCAD/bz-module-template`. Исходники, сборка и выпуски `.bzmod` ведутся в репозитории модуля. См. [ADR-0010](docs/ADR/0010-modules-in-own-repositories.md).
- Видимый текст — только `Tr("…")` / `Trf("… {}", x)`. Цвета — только токены темы.
- Переменные не называть `far` / `near` (макросы Windows).
- Без автора не трогать: `document/BzcFile*`, `JsonIO*`, `assembly/AssemblyFile*`,
  решатель сборки, `kernel/AssemblyModel*`, `AutoDrop*`, `ComponentPattern*`,
  корневой `CMakeLists.txt`, `.github/`, `third_party/`.
- Новые интерфейсы — сначала макет, в код после согласия автора.
- Не копировать код FreeCAD (LGPL).

## Сборка и проверка (WSL, путь ~/briz/breezecad)
export LD_LIBRARY_PATH=$HOME/deps/prefix/lib
# релиз (рабочий цикл, тесты ~4 мин):
cmake --build build/linux-release
./build/linux-release/bin/bz_tests
# дебаг (только для отладки крэшей, тесты ~1 ч):
cmake --build build/linux-debug

Если build/ отсутствует — конфигурировать с:
-DCMAKE_PREFIX_PATH=$HOME/deps/prefix -DOpenCASCADE_DIR=$HOME/deps/prefix/lib/cmake/opencascade

## Каждое «сделал» подтверждай
- Прогоном тестов: эталон 478/478 кейсов, 0 падений (2 808 303 ассерта).
- Или скриншотом: `scripts/ui-test/ui.sh` (Xvfb, снимки через BZ_SHOT_DIR).
Тестовая модель: `tests/data/кронштейн.bzc`. Упавший тест — чиним причину, тесты не отключаем.

## Коммиты
По-русски: `тип(область): что` (feat/fix/refactor/render/ui/docs + область).
В теле — What / Why / Where / Tested. Коммить и пушь каждую готовую часть отдельно.
Пуш — только в свою ветку; слияние PR — руками автора.

## Если задача разрастается
Остановись, кратко опиши статус и подготовь промпт для продолжения в новом чате.
