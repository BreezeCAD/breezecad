# ADR-0011: BreezCONN — передача на устройство модулем, окна модулей

- **Status:** Proposed (ждёт решения MikeVerx; кода по нему нет)
- **Date:** 2026-11-09
- **Decision makers:** Михаил Афонишев (модули, iOS); основа и ABI — MikeVerx
- **Related:** [ADR-0002](0002-module-commands-and-mcp.md), [ADR-0005](0005-module-catalog.md),
  [ADR-0010](0010-modules-in-own-repositories.md), `docs/dev/CONTINUE-ON-DEVICE.md`,
  `src/modules/bz_module.h`

## Контекст

«Продолжить на устройстве» (PR #92) влита в основу целиком: сервер на ПК,
QR, шифрование (Monocypher), окна. Работает только по кнопке, но:

- правило «офлайн, без сетевых запросов»: голая программа на ПК теперь
  умеет открыть сокет — пусть и по просьбе пользователя;
- первый запуск сервера на Windows показывает окно брандмауэра. Человек,
  скачавший «голый» Бриз, не ждёт, что программа просится в сеть;
- в `third_party` основы добавились Monocypher и qrcodegen.

Если сеть на ПК живёт в модуле, который человек поставил сам, он знает,
кто стучится в брандмауэр, а основа на ПК снова без сети.

Ограничение: на iOS (и в Google Play) скачиваемый нативный код запрещён
(ADR-0005) — модуль там не поставить. Сторона устройства остаётся в основе.

## Решение

### 1. Что где живёт

| Часть | Где | Почему |
|---|---|---|
| Сервер на ПК, QR, окно «Продолжить на устройстве», конфликты | модуль **BreezCONN** (`BreezeCAD/bz-module-conn`, id `conn`) | сеть на ПК — только с модулем |
| Приём на ПК с другого ПК («Принять с компьютера») | модуль | то же |
| Шифрование (Monocypher), qrcodegen | модуль — своя копия в его репозитории | уходят из `third_party` основы на ПК |
| Упаковка и применение изменений (`assembly/Handoff.*`, без сети) | основа, все платформы | нужна устройству; модулю — командами (п. 3) |
| Клиент на устройстве (`Fetch`/`Give`, `Seal`/`Open`), плашка «Вернуть на компьютер», ссылки `breezecad://` | основа, **только мобильные сборки** (`BZ_MOBILE`) | на iOS/Play модуль не поставить |

Итог: в сборке для ПК нет ни сокетов, ни Monocypher, ни qrcodegen. В
мобильной сборке есть только исходящее подключение по QR, который человек
сам отсканировал.

### 2. Окна модулей — расширение `bz_module.h` (ABI 2)

Модулю нужно показать пункт меню и окно. ImGui через ABI не отдаём (версия
ImGui — внутреннее дело основы). Вместо этого основа рисует **панель по
описанию** в JSON своими виджетами и темой. Ничего про передачу в основе
нет — это общие окна для любого модуля.

Хост (`BzHostApi`, новые поля, проверка `BZ_HAS`):

```c
/* Пункт меню и поиска команд. json: {"id": "conn.send", "label": "...",
 * "tooltip": "...", "icon": "export", "menu": "file"}. Нажатие —
 * on_action(id) модуля. Один id — один пункт; повтор — замена. */
int32_t (*add_action)(const char* json);
/* Включает / выключает пункт (серый, когда нечего делать). */
int32_t (*enable_action)(const char* id, int32_t enabled);
/* Показывает или обновляет панель (модальное окно основы). */
int32_t (*show_panel)(const char* json);
/* Закрывает панель. */
int32_t (*close_panel)(const char* id);
```

Модуль (`BzModuleApi`, новые поля):

```c
void (*on_action)(const char* id);           /* главный поток */
void (*on_panel_event)(const char* json);    /* главный поток */
```

Описание панели — короткий набор, которого хватает BreezCONN и
будущим модулям:

```json
{"id": "conn.send", "title": "Продолжить на устройстве", "width": 440,
 "items": [
   {"type": "text",  "text": "Наведите камеру…", "secondary": true},
   {"type": "qr",    "text": "breezecad://handoff?…", "size": 240},
   {"type": "mono",  "text": "192.168.1.5:50213"},
   {"type": "choice","id": "c1", "label": "Вал.bzc",
    "options": ["С устройства", "Своё", "Оба"], "value": 2},
   {"type": "button","id": "copy", "label": "Скопировать ссылку", "style": "link"},
   {"type": "buttons","items": [
      {"id": "apply", "label": "Применить", "style": "primary"},
      {"id": "close", "label": "Закрыть", "style": "secondary", "key": "Esc"}]}]}
```

Ещё четыре типа — их требует макет (`docs/dev/mockups/breezconn.png`):

| Тип | Что | Для чего в BreezCONN |
|---|---|---|
| `image` | картинка модуля (PNG, base64), по центру | ноутбук и планшет в окне ожидания |
| `status` | «пилюля» со статусом, `"busy": true` — с точкой-индикатором | «Жду изменения…» |
| `note` | серый текст со значком из набора основы (`"icon": "shield"`) | подсказка про брандмауэр |
| `choice` + `"preview": "<путь>"` | слева миниатюра файла — основа берёт её из `.bzc` / `.bza` | конфликты: «Вал.bzc», «Кронштейн.bzc» |

`choice` рисуется сегментами («С устройства | Своё | Оба»), как в макете.
В заголовке панели справа — значок и имя модуля (`"badge": "BreezCONN"`),
чтобы было видно, чьё это окно.

Пункт действия может стоять и на ленте: `"ribbon": {"tab": "Главная",
"group": "BreezCONN"}` — кнопка в конце вкладки, как в макете. Без
`ribbon` — только меню «Файл» и поиск команд.

Событие — `{"panel": "conn.send", "id": "apply", "values": {"c1": 0}}`;
закрытие крестиком или Esc — `{"panel": …, "id": "close"}`.

`qr` в основе — потому что QR рисуется квадратами (как сейчас `DrawQr`), а
генерация кода — 1 файл qrcodegen. Если и его не хотим в основе — вместо
`qr` тип `bitmap`: модуль сам считает матрицу (`"modules": ["0101…", …]`),
основа рисует квадраты. **Рекомендую `bitmap`** — в основе не остаётся ни
строчки про QR.

Тексты модуль присылает уже переведёнными (свой каталог строк, как у MCP).

### 3. Команды для модуля (без сети, есть и для MCP)

Модуль работает с документами командами (`host->execute`, ADR-0002).
Уже есть: `app.documents`, `doc.save`, `app.open`, `doc.close`. Добавить
три — обёртки над существующим `assembly/Handoff.*`:

| Команда | Что делает |
|---|---|
| `conn.pack` {document, package} | сохраняет и упаковывает деталь / сборку → `{session, key, files}` (сеанс модуль хранит у себя) |
| `conn.plan` {session, returned} | что пришло: обновить / конфликт / новый |
| `conn.apply` {session, returned, choices} | кладёт на место (копии прежних), открывает затронутые документы заново |

Сеть и шифрование — в модуле; основа получает и отдаёт только файлы.

### 4. Протокол — общий договор основы и модуля

Устройство (основа) и ПК (модуль) собираются раздельно, поэтому формат
обмена фиксируется здесь и меняется только с номером версии:

- QR: `breezecad://handoff?v=1&h=<IPv4>&p=<порт>&s=<32 hex>&k=<64 hex>`;
- TCP, кадр `BZH1` | тип (`G`/`P`/`R`/`K`/`E`) | длина (4 байта, big-endian) | тело;
- тело — XChaCha20-Poly1305 (Monocypher), ключ из QR, сеанс — связанные данные;
- пакет — `.bzp` + `handoff.json`; возврат — ZIP изменённых файлов + `handoff.json`.

Подробно — `docs/dev/CONTINUE-ON-DEVICE.md`.

### 5. Что убрать из основы на ПК (после модуля)

`assembly/HandoffNet.cpp` (сервер), окно отправки и `file.handoff` в
`app/handoff/HandoffUi.cpp`, `third_party/qrcodegen`, Monocypher из
сборки ПК, подсказка про брандмауэр. Делать **после** выпуска модуля,
чтобы функция не пропала между версиями.

## Порядок

1. Это ADR + макет окна (`docs/dev/mockups/breezconn.png`: QR, ожидание,
   конфликты) → «да» MikeVerx.
2. Основа: ABI 2 (окна модулей) + команды `conn.*` — один PR.
3. Шаблон модулей (`bz-module-template`): `sdk/bz_panel.h`, пример окна,
   тест — один шаблон на все модули, отдельного «с окнами» нет (иначе две
   копии `bz_module.h`).
4. `bz-module-conn` из шаблона: сервер, QR, окна по макету, тесты.
5. Основа: убрать сетевое с ПК (п. 5) — отдельный PR после выпуска модуля.

## Consequences

- Плюс: основа на ПК снова без сети — правило «офлайн» без оговорок.
- Плюс: брандмауэр спрашивает про модуль, который человек поставил сам.
- Плюс: окна модулей пригодятся не только BreezCONN (MCP — статус и токен,
  будущие модули) — без ImGui в ABI.
- Минус: на ПК без модуля нельзя ни отдать, ни принять проект.
- Минус: протокол — договор между двумя репозиториями; менять — с версией.
- Минус: ABI растёт (4 поля хоста, 2 модуля) — навсегда, как любое ABI.

## Alternatives

- **Оставить как есть (в основе).** Работает уже сейчас, но спорит с
  правилом «офлайн» и пугает брандмауэром.
- **ImGui-контекст модулю.** Полная свобода окон, но ABI зависит от версии
  ImGui и шрифтов основы — любое обновление ломает модули.
- **Модуль и на устройстве.** На iOS и в Play нельзя (ADR-0005).
