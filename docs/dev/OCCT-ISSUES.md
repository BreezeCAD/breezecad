# Особенности и сбои OCCT

Что геометрическое ядро делает не так и как программа это обходит. Правило
(STAB-3): каждое падение или неверный результат внутри OCCT — минимальный
`.brep` в `tests/data/occt/` и тест в `tests/kernel/OpsTests.cpp` («occt: …»):
он показывает, что делает голый OCCT, и что из этого делает конвейер
`kernel/occt/Ops`. При обновлении OCCT (`BreezeCAD/occt`) тест, у которого
перестала сходиться «голая» проверка, значит: OCCT там изменился — посмотреть,
нужен ли ещё обход.

Как поймать новый случай: запустить программу или тесты с
`BZ_OCCT_DUMP=<папка>` — при сбое внутри булевой операции `Ops` пишет туда её
аргументы (`fault-cut-1.brep` и т. п.). Только для разработчиков: программа
ничего никуда не отправляет. Из такого файла делается минимальный случай
(оставить только то, без чего сбой пропадает) и записывается сюда.

Версия ядра во всех записях — OCCT 8.0.1 (`dev-deps`, Linux x86_64), если не
сказано иное.

## №1 — Склейка (SetGlue) пересечения с полупространством даёт неверное тело
- **Файл:** `tests/data/occt/glue-halfspace-common.brep` — куб 10×10×10 и
  полупространство z < 4.
- **Голый OCCT:** `BRepAlgoAPI_Common` с `SetGlue(BOPAlgo_GlueShift)` — IsDone,
  без ошибок, объём результата 200 000 мм³ вместо 400.
- **Обход:** склейка — только запасная попытка после точной и с допуском;
  любой результат проверяется по объёму (пересечение не больше меньшего из
  тел; у полупространства объёма нет — граница не ставится, проверяется
  остальное). Здесь точная попытка верна, до склейки не доходит.
- **Тест:** `occt: a glued intersection with a half-space gives a wrong body`.

## Известно, но без минимального файла
- **Скругление на конце ребра, упирающегося в стенку паза** (BETA-BUGS №8):
  `Geom_TrimmedCurve::parameters out of range` и сбой в
  `ChFi3d_StripeEdgeInter` (OCCT 7.8). Есть только на закрытой детали тестера
  («Кубик монолит»); при появлении — снять `.brep` через `BZ_OCCT_DUMP`
  (для скругления дамп пока не пишется — только для булевых).
- **Неразрушающий режим.** До STAB-3 точный вырез пружиной с вершинами на
  стенке в модели давал тело с ребром при одной грани; с
  `SetNonDestructive(true)` — нет. Из записанных в файл тела и инструмента
  это не воспроизводится (OCCT поднимал допуски у тел, сохранённых моделью
  раньше), поэтому случая с файлом нет — запись на память.
- **`BOPAlgo_AlertBOPNotAllowed`** на стенде (`part_history`): вырез
  инструментом, который не является телом. Не сбой ядра — честный отказ;
  пользователь видит «Ядро не смогло выполнить вырез…».
