# ADR-0013: Распознавание конструктивных элементов в импортированной геометрии

- **Status:** Proposed (черновик, этапы 1–4 — план; этап 0 сделан)
- **Date:** 2026-11-09
- **Related:** [ADR-0012](0012-drawings.md) (ветка `docs/drawings`: общий контейнер `.bzc`/`.bza`/`.bzd`
  и правила совместимости формата), [ADR-0001](0001-kernel-strategy.md)

## Context

Задумка автора (09.11.2026): импорт STEP с восстановлением детали **методом
построения** — дерево операций по геометрии, без чтения чужих форматов САПР
(`.ipt`, `.sldprt`, `.m3d` по-прежнему не читаем, PHILOSOPHY §5). Импорт нужен
и для STL — основного формата слайсеров. Сложные криволинейные модели
(«аниме-фигурки») восстанавливать не надо: для них хватает тела как есть.

**Этап 0 (сделан, ветка `feat/import-step-stl`):** STEP (AP203/AP214/AP242)
и STL (двоичный и текстовый) открываются в программе операцией
«Импортированное тело» (`doc::ImportFeature`, `kernel/Import.h`).

- Геометрия хранится **внутри файла детали** (сжатый BRep OCCT версии 3 или
  собственная сетка, base64 в JSON, CRC-32), а не ссылкой на `.step`: деталь
  переезжает между ПК и телефоном. Путь к исходнику запоминается для
  «Обновить из файла».
- **Формат опирается на общий контейнер** (`WriteBzcArchive`/`ReadBzcArchive`,
  общий с `.bza` и `.bzd` по ADR-0012) и его не меняет: импортированное тело —
  обычная операция детали в `document.json`, без своих записей в архиве и
  ключей манифеста. Правила совместимости — те же, что ADR-0012 §3 вводит для
  чертежа: ключи только добавляются; блок геометрии с тегом версии (`BZB1`,
  `BZM1`), новый блок — новый тег, старые читаются всегда; операция, которую
  программа не может прочесть (новее или повреждена), хранится как есть
  (`UnknownFeature`) и записывается обратно без изменений; эталонные файлы —
  `tests/data/import/v1/`, удалять нельзя.
- STEP: единицы файла → мм, лечение `ShapeFix_Shape`, несколько тел → несколько
  тел детали, замкнутые оболочки → тела, незамкнутые — поверхности
  (предупреждение), AP242 только с сеткой → тело-сетка.
- Поверх точного тела работают обычные операции (эскиз на грани, выдавливание,
  вырез, отверстия, фаски, скругления, проецирование рёбер).
- STL → тело-сетка (грань без поверхности с `Poly_Triangulation`): показ,
  выбор, измерения, МЦХ, экспорт в STL/3MF; в булевых и операциях на телах не
  участвует. Лимит треугольников (ПК 500 000, телефон 250 000) с предложением
  упростить сетку (кластеризация вершин, детерминированно).

Этот ADR — план следующих этапов: из «немого» импортированного тела получить
редактируемое дерево построения, которое конструктор проверит своими глазами.

> **PHILOSOPHY §5 поправлен (09.11.2026, по решению автора).** Раньше там
> «Обратный инжиниринг (mesh → solid)» стоял в отвергнутых целиком. Теперь
> отвергнут только обратный инжиниринг свободных форм; mesh → solid —
> для призматических деталей из простых примитивов (этап 3 ниже).

## Decision

### Общие правила для всех этапов

1. **Без нейросетей.** Только детерминированные алгоритмы: один и тот же файл
   на любой машине и в любой версии ядра даёт одно и то же дерево. Случайные
   выборки (RANSAC) — с фиксированным зерном, порядок обхода — по
   устойчивому порядку граней (по площади, затем по центру), а не по
   порядку OCCT.
2. **Сверка с оригиналом обязательна.** После распознавания строим дерево и
   сравниваем с исходным телом: объём (относительная разница), площадь,
   отклонение — расстояние Хаусдорфа по точкам на гранях. Не прошло порог —
   распознанное откатывается к «Импортированному телу» (частично или целиком).
3. **Нераспознанный остаток не теряется.** То, что не удалось выразить
   операциями, остаётся «Импортированным телом» в начале дерева; распознанные
   операции идут поверх него (вычитание/добавление). Деталь всегда совпадает
   с файлом.
4. **Лимит сложности** — до распознавания, по двум числам тела:
   - доля площади **свободных поверхностей** (B-сплайны, Безье, поверхности
     вращения произвольного профиля, смещённые) в общей площади;
   - **число граней**.

   | Режим | Условие (ориентир, подобрать на тестовом наборе) |
   |---|---|
   | **Полностью** | свободных ≤ 5 % площади и граней ≤ 2 000 |
   | **Частично** | свободных ≤ 40 % — распознаём аналитическую часть, остальное — тело |
   | **Только тело** | свободных > 40 % или граней > 20 000 (фигурки, скульптуры, сканы) |

   Режим показывается до запуска, пользователь может понизить его вручную
   («только тело» для всего). Повысить нельзя: защищаем время пользователя.
5. **Всё фоновое и отменяемое**, как импорт этапа 0: прогресс, отмена,
   `FaultGuard`. Результат — одна команда отмены (Ctrl+Z возвращает тело).
6. **Код — в `src/recognition/`** (новый модуль, зависит от `kernel`), без
   интерфейса; интерфейс — отдельно, макетом до кода.
7. **Формат не трогаем.** Распознанные операции — обычные операции детали
   (эскизы, выдавливания, отверстия), остаток — «Импортированное тело» того же
   формата. Новые ключи — только добавлением (ADR-0012 §3).

### Этап 1 — отверстия, скругления, фаски на импортированном STEP

- **Граф смежности граней** (Attributed Adjacency Graph): узел — грань (тип
  поверхности, площадь, нормаль/ось, радиус), ребро — общее ребро (выпуклое,
  вогнутое, гладкое — по углу между нормалями вдоль ребра).
- **Отверстия:** цилиндрическая грань «внутрь» (`FaceInfo::hole` уже есть)
  + дно (плоское / коническое 118°) + зенковка/цековка по соседям вдоль оси.
  Результат — операция «Отверстие» с типом, ⌀, глубиной, а соосные одинаковые
  на одной плоскости — кандидаты в «Массив».
- **Скругления:** цилиндрическая/тороидальная полоса, гладко сопряжённая с
  двумя соседями, постоянный радиус по цепочке рёбер → «Сопряжение».
- **Фаски:** плоская полоса между двумя гранями, постоянные катеты → «Фаска»
  (два размера или с углом).
- Снятие с тела: `BRepAlgoAPI_Defeaturing` (OCCT 7.4+) удаляет распознанные
  грани; что осталось — новое «Импортированное тело», распознанное — операции
  поверх него. Сверка: дерево перестраивается и сравнивается с исходником.
- Порядок снятия: сначала скругления и фаски (мелкие), затем отверстия — так
  `Defeaturing` надёжнее закрывает «дыры».

### Этап 2 — выдавливания и вращения → эскизы с зависимостями и размерами

- Тело после этапа 1 раскладываем на **призматические** (все боковые грани
  параллельны одному направлению, торцы — плоские) и **тела вращения**
  (все грани — поверхности вращения вокруг одной оси).
- Профиль — сечение плоскостью торца / осевое сечение → эскиз: отрезки и дуги
  (из рёбер сечения), **зависимости** (горизонтальность, вертикальность,
  параллельность, перпендикулярность, касание, совпадение, концентричность,
  равенство — по допускам) и **размеры** так, чтобы эскиз стал полностью
  определённым (решатель `sketch::Solve` и анализ степеней свободы уже есть).
- Разбиение: от большего объёма к меньшему, «бобышки» — «Объединение»,
  карманы — «Вычитание»; выдавливание «до грани», если торец лежит на грани
  соседа.
- **Сверка** (обязательно): объём и отклонение. Нераспознанный остаток —
  «Импортированное тело».

### Этап 3 — STL → подгонка примитивов → тот же распознаватель

- **Сегментация сетки:** рост областей по нормалям и кривизне (детерминированный
  порядок затравок — по площади треугольника).
- **Подгонка:** плоскости, цилиндры, конусы, сферы, торы — RANSAC с
  фиксированным зерном + уточнение МНК; области без хорошей подгонки —
  свободная поверхность (→ по лимиту сложности «частично» / «только тело»).
- **«Округление замысла»:** притягивать параметры к круглым числам и
  стандартным значениям, если это укладывается в допуск подгонки:
  длины и ⌀ — к 0,1 / 0,5 / 1 мм; отверстия — к ряду крепежа (М3 → ⌀3,2/3,4…);
  углы — к 0°, 15°, 30°, 45°, 60°, 90°; параллельность и перпендикулярность —
  точно. Допуск — от шума скана (оценка по остаткам подгонки), не жёсткий.
- Из подогнанных граней — B-rep (пересечение примитивов), затем этапы 1–2
  без изменений. Сверка — расстояние от вершин сетки до тела.

### Этап 4 — сборки из STEP

- Структура сборки из STEP (XCAF: `TKXCAF` + `TKXDESTEP`, уже есть в пакетах
  CI) → `.bza` + детали `.bzc` в общем контейнере (ADR-0012); одинаковые
  детали — один файл, несколько экземпляров.
- Зависимости восстанавливаются по геометрии в положении из файла:
  **соосность** цилиндрических граней разных деталей → «Вставка»/«Совмещение
  осей»; **совпадающие плоскости** (противоположные нормали, расстояние ≈ 0) →
  «Совмещение»; параллельные с зазором → «Совмещение» со смещением. Остаток
  степеней свободы — фиксация, чтобы сборка не «поехала».
- Правило дубликатов сборок (детали рядом со сборкой) соблюдается.

## Consequences

- Пользователь получает **редактируемую** деталь там, где геометрия это
  позволяет, и честное «тело как есть» там, где нет — без «чёрного ящика»:
  каждый шаг виден в дереве, каждое распознавание сверено с исходником.
- Новый модуль `src/recognition` с тестами на сгенерированных OCCT файлах
  (как в этапе 0) и на наборе реальных STEP/STL (лицензия файлов — проверить).
- Этап 1 опирается на `BRepAlgoAPI_Defeaturing` — у OCCT бывают отказы на
  сложных телах; их ловит сверка, а не пользователь.
- Этап 4 добавляет зависимость `TKXCAF`/`TKXDESTEP` (сейчас линкуется только
  `TKDESTEP`) — увеличит пакет; оценить размер перед решением.
- Порядок по трудоёмкости: 1 (≈ 1–2 сессии) → 2 (2–4) → 4 (2–3) → 3 (самый
  длинный и рискованный). Возможно, этап 4 стоит сделать раньше 3.

## Alternatives

- **Нейросетевое распознавание** (BRepNet, UV-Net и т. п.) — отвергнуто
  автором: недетерминированно, тяжело для слабых ПК и телефона, непроверяемо.
- **Чтение истории построения из нативных форматов** (`.ipt`, `.sldprt`) —
  закрытые форматы, лицензии, PHILOSOPHY §5.
- **Только «тело как есть» навсегда** (как во многих бесплатных САПР) — не
  отвечает задаче автора: перенести свои наработки из Inventor в
  редактируемый вид.
- **Синхронное (прямое) моделирование** поверх тела вместо дерева —
  отвергнуто PHILOSOPHY §5 и не даёт дерева построения.
