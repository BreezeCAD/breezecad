# «Продолжить на устройстве» — план

Статус: идея одобрена Михаилом 08.11.2026, делается **после первой стабильной
версии**. Ветка — `feat/continue-on-device`.

## Зачем

Работаешь на ПК, надо отойти — передал открытую деталь или сборку на
планшет/телефон (iOS, Android) и продолжил там с того же места. Потом вернул
изменения на ПК.

## Рамки (из `docs/PHILOSOPHY.md` и правил продукта)

- Только локальная сеть, напрямую ПК ↔ устройство. Без облака, серверов,
  аккаунтов и телеметрии.
- Сервер на ПК поднимается только на время передачи и слушает только её.
- Формат `.bzc` / `.bza` не меняем.

## Решено

1. **QR показывает ПК, сканирует устройство** — в обе стороны (у ПК обычно нет
   камеры). «Продолжить на устройстве» — устройство забирает проект;
   «Принять с устройства» — устройство отдаёт изменения.
2. **QR привязан к конкретному проекту** — к открытой детали или сборке. По
   нему можно забрать только этот проект и вернуть изменения только в него.
   Возврат с другим проектом или чужим токеном отклоняется.
3. Пока окно передачи на ПК открыто, возврат — одной кнопкой «Вернуть на ПК»,
   без второго QR. Окно закрыли — нужен новый QR.
4. **Только ПК → устройство → ПК.** Цепочек (устройство → устройство) пока нет.
5. ~~Кэш геометрии — галочкой~~ — не нужно: в `.bzc` кэша нет (только
   `manifest.json`, `document.json`, картинки, `preview.png`), устройство и так
   перестраивает модель по рецепту.
6. **После возврата копия на устройстве удаляется.**
7. Обратно едут только изменённые файлы. Если файл на ПК тоже менялся после
   отправки — окно выбора по каждому файлу: «Взять с устройства / Оставить своё /
   Сохранить обе», с миниатюрами (как окно изменений #84).

## Как устроено (черновик)

**Транспорт — существующий `.bzp`** (`assembly/ProjectPack.*`, см.
`docs/ASSEMBLY_FORMAT.md`): сборка и все её детали в одном ZIP. Для детали —
пакет из одного файла. Добавить:

- в `project.json` — блок передачи: ID сеанса, хеш каждого файла на момент
  отправки, состояние вида (камера, активный эскиз/операция) — чтобы продолжить
  с того же места (сделано отдельной записью `handoff.json`: `project.json`
  не меняется).

**QR:** адрес ПК в локальной сети, порт, ID сеанса (= проекта) и одноразовый
ключ. Передача шифруется этим ключом.

**Возврат на ПК:** ПК помнит, откуда взят каждый файл пакета (`.bzp` кладёт
детали из чужих папок рядом со сборкой и переименовывает при совпадении — при
возврате их надо разложить обратно по исходным путям). Пути хранит программа,
не файл.

## Проверено

- Стандартные изделия — обычные `.bzc` в «Стандартные изделия/» рядом со
  сборкой (на Android — в той же папке): `.bzp` берёт их как любые детали.

## Сделано (этап 1 — без сети и окна)

`assembly/Handoff.*`, тесты `tests/assembly/HandoffTests.cpp`:

- `Send` — пакет для детали или сборки: `.bzp` + `handoff.json` (сеанс, главный
  документ, вид, SHA-256 файлов). Ключ и пути ПК в пакет не попадают —
  остаются в `Session` (`SaveSession` / `LoadSession`).
- Устройство: `ReadTicket` → `UnpackProject` → `PackReturn` (только изменённые
  и новые документы).
- ПК: `PlanReturn` (принимает только свой сеанс; «Обновить / Конфликт /
  Новый»), `ApplyReturn` (выбор по файлу, прежний файл — в копии, сборке
  возвращаются пути деталей как на ПК).
- `QrText` / `ParseQr` — содержимое QR.
- `Seal` / `Open` — шифрование ключом из QR (решено 08.11.2026: Monocypher
  4.0.2, XChaCha20-Poly1305, `third_party/monocypher`, лицензия CC0 — без
  обязательств). Номер сеанса вшит в подпись: пакет другого проекта не
  откроется.
- В `ProjectPack`: `PackReport::packed` (откуда взята каждая деталь) и общая
  `SafeArchivePath`.

## Сделано (этап 2 — сеть)

`assembly/HandoffNet.*`:

- `Server::Start` — слушает все сети ПК на свободном порту, адрес для QR
  (`LocalAddress` — без отправки пакетов). Пустой хост = ПК не в сети.
- `Server::Serve(timeout)` — одно подключение за вызов, блокирует: окно зовёт
  его из рабочего потока. События: `Sent`, `Returned` (данные — пакет для
  `PlanReturn`), `Refused` (чужой ключ — ответа по сути нет), `None`.
- Устройство: `Fetch` (забрать проект), `Give` (вернуть изменения).
- Протокол: кадр `BZH1` | тип | длина | тело, тело всегда через `Seal`.
  Предел передачи — 256 МиБ.
- Тест — на 127.0.0.1: забрать, чужой ключ, вернуть, остановка.

Известное:
- Повтор перехваченного `Give` в той же сети пройдёт (данные те же,
  расшифровать их нельзя); защита — счётчик в сеансе, если понадобится.
- Windows при первом запуске сервера спросит про брандмауэр — показать
  в окне подсказку.
- Android: в манифесте сейчас нет ни одного разрешения — нужны `INTERNET`
  (и камера для QR). iOS: `NSLocalNetworkUsageDescription`.
