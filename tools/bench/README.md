# Стенд испытаний BreezeCAD

Проверяет программу так, как с ней работает человек: настоящая мышь и
клавиатура на виртуальном экране (Linux, Xvfb), детали и сборки строятся
руками, а результат сверяется с эталоном, построенным командами.

Отличие от `scripts/ui-test`: сценарий не знает координат. Программа сама
отвечает, где на экране кнопка, поле или строка дерева и в какой пиксель
попадает точка модели или эскиза (`src/app/testing/UiProbe`). Правка
интерфейса сценарии не ломает.

## Запуск

```bash
cmake --preset linux-debug -DBZ_UI_PROBE=ON && cmake --build --preset linux-debug
export LD_LIBRARY_PATH=$HOME/deps/prefix/lib:$LD_LIBRARY_PATH PATH=$HOME/deps/bin:$PATH
python3 tools/bench/run.py            # все сценарии
python3 tools/bench/run.py plate      # один, по части имени
```

Зонд выключен, пока не задана переменная `BZ_PROBE_DIR`; в сборках для
пользователей (`BZ_UI_PROBE=OFF`) его перехватчиков нет вовсе. Обмен идёт
файлами в этой папке — без сети.

## Как писать сценарий

Файл `scenarios/<имя>.py` с функцией `run(b)`, где `b` — `bench.Bench`:

| Что | Как |
|---|---|
| кнопка ленты, шапки, панели | `b.click("feature.extrude")`, `b.click("done")` |
| строка дерева, вкладка | `b.click("tree:Эскиз1", double=True)`, `b.click("tab:Вид")` |
| поле панели | `b.fill("Расстояние", 25)` |
| точка модели / эскиза | `b.click_world(x, y, z)`, `b.click_sketch(u, v)` |
| клавиши, ввод | `b.key("r")`, `b.enter(120)` |
| дождаться конца перестроения | `b.settle()` |
| прочитать, что получилось | `b.run("part.properties")` |
| снимок окна | `b.shot_png("имя")` |

Точка вне вида или под видовым кубом — ошибка сценария: стенд скажет об
этом, а не щёлкнет по ленте.

После сценария стенд сам проверяет журнал программы: срабатывание
предохранителя (`Recovered:`), сообщения санитайзера и вылет — всегда провал.
