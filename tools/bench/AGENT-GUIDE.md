# Памятка испытателю (для ИИ-агентов и людей)

Цель испытаний — чтобы пользователь не встретил ни одного бага. Проверяем
программу руками (мышь, клавиатура), а не командами. Там, где поведение не
описано в документах проекта, эталон — Autodesk Inventor.

## Запуск

```bash
cd /home/claude/breezecad
export LD_LIBRARY_PATH=$HOME/deps/prefix/lib:$LD_LIBRARY_PATH PATH=$HOME/deps/bin:$PATH
export BZ_BENCH_DISPLAY=:101          # свой экран у каждого испытателя
python3 tools/bench/run.py <часть имени сценария> --work /home/claude/run/<своя папка>
```

Пробовать по шагам удобнее так (каждый раз новая программа, 5 с на запуск):

```python
import sys; sys.path[:0] = ["tools/bench", "tools/bench/scenarios"]
from bench import Bench; from _common import *
with Bench(work="/home/claude/run/<своя папка>/try") as b:
    new_part(b); start_sketch_on_xy(b)
    print(b.brief(), b.panel())        # что сейчас на экране
```

## Чем смотреть (дёшево → дорого)

1. `b.brief()` — режим, инструмент, открытая операция, сообщения на экране.
2. `b.panel()` — что в левой панели; `b.labels("ribbon")`, `b.labels("Popup")`,
   `b.windows()` — что в других окнах и меню.
3. `b.run("part.tree")`, `part.properties`, `part.faces`, `part.edges`,
   `sketch.get {sketch: id}`, `assembly.components` — что получилось в модели.
   Все команды с описанием аргументов: `/home/claude/run/commands.json`.
4. `b.shot_png("имя")` и посмотреть картинку — только когда без глаз нельзя
   (дефект отрисовки, непонятное состояние). Картинки дорогие.

## Как называть то, по чему щёлкаем

- действия ленты и шапки — их id: `sketch.start`, `feature.extrude`, `file.save`
  (полный список — `grep -o '"[a-z]*\.[A-Za-z0-9]*"' src/app/AppActions.cpp`);
- кнопки панели операции: `done`, `apply`, `cancel`, `close-op`; эскиз: `pinned-finish`;
- строка дерева: `tree:Эскиз1`; вкладка ленты: `tab:Вид`; вкладка документа: `doc:Деталь1`;
- поле значения — по подписи над ним: `b.fill("Расстояние", 25)`;
- переключатель-иконка — по подсказке: `b.click("Вырезать из тела")`; когда подпись
  длинная — `b.click("depth|Насквозь", exact=False)`;
- незнакомое — сначала `b.panel()`.

## Что уже известно о программе (чтобы не открывать заново)

- Мышь по умолчанию: ПКМ с протяжкой — вращение, средняя — сдвиг, колесо — масштаб.
- Клавиши: S эскиз, E выдавливание, R вращение (в эскизе R — прямоугольник), H отверстие,
  D размер, L отрезок, C окружность, O эквидистанта, F — «Показать всё» (не сопряжение),
  Esc ×3 — выйти из эскиза, Enter — «Готово».
- Эскиз привязывается к сетке: нарисованное «на глаз» встаёт на её шаг. Где сейчас линия —
  читать `sketch.get`, а не верить своим координатам.
- Первый размер эскиза масштабирует весь эскиз (так задумано, как в Inventor).
- Размер: щелчок по элементу, щелчок по свободному месту — открывается поле значения.
- X/Y в панели «Отверстие» — координаты модели.
- Программа рисует кадр только при изменениях; после действий — `b.settle()`.
- Точка вне вида или под видовым кубом — стенд откажется щёлкать: сначала впишите
  вид (`view.fit`, колесо) или поверните его.

## Что считать находкой

Перед тем как записать, повторите дважды и исключите ошибку самого сценария
(щелчок мимо, слишком рано прочитанное состояние, не та подпись).

- **баг** — вылет, зависание, `Recovered:` в журнале (`b.problems()`), неверная
  геометрия, потерянные данные, операция с ошибкой там, где она должна строиться,
  отмена/повтор, которые не возвращают прежнее состояние, дефект отрисовки;
- **несоответствие Inventor** — действие, которое в Inventor делается привычно,
  а здесь не работает или требует лишних шагов;
- **лаг** — действие дольше 1 с на простой модели (софтверный OpenGL медленный:
  судить по времени операции, не по кадрам).

Запись находки: шаги (сценарий, который её повторяет), что ждали, что вышло,
где в коде причина (файл:строка, если нашли) и как предлагаете чинить.

## Правила

- Код программы (C++) не править и ничего не собирать: сборка одна на всех.
  Чинит ведущий — по вашим находкам.
- Сценарии — в `tools/bench/scenarios/<область>_<что>.py`: функция `run(new)`,
  эталон командами и по возможности два разных ручных способа; сравнение — `same_part`.
- Сценарий, который проходит, должен проходить три раза подряд.
- `modules/mcp`, форматы файлов, CI не трогать.
