# «Продолжить на устройстве» — план

Статус: идея одобрена Михаилом 08.11.2026, делается **после первой стабильной
версии**. Ветка — `feat/continue-on-device`.

## Зачем

Работаешь на ПК, надо отойти — передал открытую деталь или сборку на
планшет/телефон (iOS, Android) и продолжил там с того же места. Потом вернул
изменения на ПК.

## Рамки (из `docs/PHILOSOPHY.md` и правил продукта)

- Только локальная сеть, напрямую ПК ↔ устройство. Без облака, серверов,
  аккаунтов и телеметрии.
- Сервер на ПК поднимается только на время передачи и слушает только её.
- Формат `.bzc` / `.bza` не меняем.

## Решено

1. **QR показывает ПК, сканирует устройство** — в обе стороны (у ПК обычно нет
   камеры). «Продолжить на устройстве» — устройство забирает проект;
   «Принять с устройства» — устройство отдаёт изменения.
2. **QR привязан к конкретному проекту** — к открытой детали или сборке. По
   нему можно забрать только этот проект и вернуть изменения только в него.
   Возврат с другим проектом или чужим токеном отклоняется.
3. Пока окно передачи на ПК открыто, возврат — одной кнопкой «Вернуть на ПК»,
   без второго QR. Окно закрыли — нужен новый QR.
4. **Только ПК → устройство → ПК.** Цепочек (устройство → устройство) пока нет.
5. **Кэш геометрии — галочкой** (по умолчанию без кэша: пакет лёгкий,
   устройство пересчитывает с прогрессом).
6. **После возврата копия на устройстве удаляется.**
7. Обратно едут только изменённые файлы. Если файл на ПК тоже менялся после
   отправки — окно выбора по каждому файлу: «Взять с устройства / Оставить своё /
   Сохранить обе», с миниатюрами (как окно изменений #84).

## Как устроено (черновик)

**Транспорт — существующий `.bzp`** (`assembly/ProjectPack.*`, см.
`docs/ASSEMBLY_FORMAT.md`): сборка и все её детали в одном ZIP. Для детали —
пакет из одного файла. Добавить:

- в `project.json` — блок передачи: ID сеанса, хеш каждого файла на момент
  отправки, состояние вида (камера, активный эскиз/операция) — чтобы продолжить
  с того же места;
- режим «без кэша» (галочка).

**QR:** адрес ПК в локальной сети, порт, ID сеанса (= проекта) и одноразовый
ключ. Передача шифруется этим ключом.

**Возврат на ПК:** ПК помнит, откуда взят каждый файл пакета (`.bzp` кладёт
детали из чужих папок рядом со сборкой и переименовывает при совпадении — при
возврате их надо разложить обратно по исходным путям). Пути хранит программа,
не файл.

## Открыто — проверить до начала

- Стандартные изделия в сборке: попадают ли они в `.bzp` и как (ссылка на
  `.bzlib` или отдельный `.bzc`).
- iOS: разрешение на локальную сеть (`NSLocalNetworkUsageDescription`,
  `NSBonjourServices`), приём только при открытом приложении. iOS ведёт второй
  разработчик (#85) — согласовать с ним.
- Чем шифровать без тяжёлых зависимостей (лёгкость, ARM).
- Где в `platform` камера для сканирования QR на Android/iOS.
