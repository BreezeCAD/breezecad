# Проверка «сделал — удостоверился»

Цель — убедиться, что правка ничего не сломала, и отчитаться автору коротко.

## 1. Где мы
- Linux (облачная песочница или машина с зависимостями): пресет `linux-debug`.
  В свежей облачной песочнице сначала `bash scripts/dev/cloud-setup.sh`
  (HANDOFF §0), затем `export LD_LIBRARY_PATH=$HOME/deps/prefix/lib:$LD_LIBRARY_PATH`.
- Windows/macOS без локальной сборки — собирать нечем: закоммитить, пушнуть
  ветку и проверить CI скиллом `/ci-triage` (один раз, не в цикле).

## 2. Сборка
```bash
cmake --preset linux-debug >/dev/null && \
cmake --build --preset linux-debug -- -k 0 2>&1 | grep -E "error|warning:" | head -30
```
Предупреждения в изменённых файлах — исправить; чужие старые — не трогать.

## 3. Тесты
```bash
ctest --preset linux-debug --output-on-failure 2>&1 | tail -15
```
Если правка затрагивает конкретный модуль — сначала его тесты
(`./build/linux-debug/bin/bz_tests -tc="*имя*"`), потом все.
Новая функция без теста — добавить тест в `tests/<модуль>/`.

## 4. Переводы
Если в правке есть новые `Tr("…")` / `Trf(…)` / `N_(…)`:
```bash
python3 scripts/i18n/extract.py
```
и закоммитить обновлённый `translations/template.json` вместе с правкой.

## 5. UI (только если менялся интерфейс)
Подходящий сценарий из `scripts/ui-test/scenario-*.sh` или мониторинг
`python3 tools/monitor/run.py --scenario bracket` (HANDOFF §3, §3а).
Скриншоты — только когда без них нельзя.

## 6. Итог автору (2–4 строки)
- «Сборка и N тестов — зелёные» или что именно упало и почему.
- Что не проверено (например, «Windows — только через CI»).
