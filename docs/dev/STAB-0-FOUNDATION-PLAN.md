## 1. Одна версия OCCT везде

Сейчас (по `build.yml` и скриптам, 12.11.2026):

| Где | Откуда OCCT | Версия |
| --- | --- | --- |
| Windows (CI, выпуски) | пакет MSYS2 `mingw-w64-x86_64-opencascade` | какая свежая на день сборки (по комментариям в коде — 8.x) |
| Linux (CI, выпуски) | conda-forge `occt=*` | любая подходящая на день сборки |
| Linux, проверка `linux-occt76` | Ubuntu 24.04 `libocct-*` | 7.6 |
| macOS | Homebrew `opencascade` | какая свежая на день сборки |
| Android, iOS | из исходников, `scripts/*/build-deps.sh` | V8_0_1 |
| Облачная песочница Claude | `scripts/dev/cloud-setup.sh` | V7_8_1 |

Следствие: один и тот же `.bzc` строится разными алгоритмами на разных ОС и в разные дни. В коде уже есть
обходы падений, известных «только в OCCT 8 из MSYS2» (FaceMatch.cpp, Extrude.cpp) и «только в 7.8»
(BETA-BUGS №8). Тесты в песочнице идут на 7.8.1, пользователи Windows — на 8.x: тест зелёный, у тестера падает.
Замер 13.11.2026: «Кубик монолит - угол 3.bzc» без изменений — на Windows-билде 0.2.5.1 (MSYS2) тело из **421** грани,
в песочнице (OCCT 7.8.1) — из **394**. Один файл, разная топология: ссылки на грани и рёбра ведут себя по-разному.
Ещё пример — комментарий в tests/kernel/ThreadTests.cpp: резьба падала только на Windows (OCCT 7.9.3 из MSYS2).

Предложение:
- **Версия:** V8_0_1 на всех платформах (уже стоит на Android/iOS).
- **Сборка:** из исходников, как `scripts/android/build-deps.sh`: общий скрипт `scripts/deps/build-occt.sh <платформа>`
  с одним `OCCT_TAG`, только тулкиты из ADR-0001. Кэш Actions по хешу скрипта: первая сборка ~1 ч на ОС, дальше минуты.
  Песочница качает тот же архив (релиз `dev-deps`) — тесты Claude идут на той же версии, что у пользователей.
- **Форк `BreezeCAD/occt`:** источник сборки — ветка `bz/V8_0_1` = тег + наши патчи (пока ноль). Нужен, когда
  появится первый патч к падению внутри OCCT; до этого можно собирать прямо с тега `Open-Cascade-SAS/OCCT`.
- **`linux-occt76`:** убрать (7.6 мы не поставляем, она только расходует время CI).
- **Обновление OCCT** — отдельный PR, который меняет только `OCCT_TAG` и проходит эталонные файлы (пункт 3).

## 2. Версия ядра — видна

- В «О программе», в отчётах о сбоях и зависаниях, в `bz_tests` (первая строка вывода): `OCC_VERSION_COMPLETE`.
  Это не защищённые файлы — можно сделать сразу.
- В `manifest.json` нового поля `"kernel": "OCCT 8.0.1"` — **формат, нужно «да» автора.** Поле только
  добавляется, старые версии его игнорируют (`ReadMember`).

## 3. Эталонные файлы (сделано в этой ветке, без CI)

- Открытые: `tests/data/corpus/0.2/*.bzc` + `*.expect.json` — только детали, которые можно показывать всем.
- Закрытые (настоящие конструкции автора и тестеров, «Кубик монолит» и т.п.): отдельный **закрытый** репозиторий
  `BreezeCAD/bz-test-corpus` с той же раскладкой; тест берёт их из переменной `BZ_CORPUS_DIR`. CI достаёт его вторым
  `actions/checkout` по токену из секрета (fine-grained, только чтение этого репо). В PR из чужих форков секретов
  нет — там идут только открытые детали.
- Файлы эталонов: состояние каждой операции, объём/площадь/габарит/число граней тел.
- Тест `corpus: …` перестраивает каждый файл и сравнивает; при расхождении называет первую разошедшуюся операцию.
- Эталоны пишутся только руками: `BZ_CORPUS_WRITE=1 ./bz_tests -tc="corpus*"`, с причиной в коммите.
- Эталон «Кубика» фиксирует **текущее** поведение, в том числе ошибочное: этапы 2–5 меняют его осознанно.

## 4. Быстрый набор тестов

Полный прогон в debug — 30+ мин на 2 ядрах, регрессии ловятся поздно. Предложение: тег `[fast]` у тестов ядра,
документа, эталонов и SourceRules (цель — до 3 мин в release на 2 ядрах) — на каждый PR; полный набор — ночью
по расписанию и перед выпуском. Нужна правка `.github/workflows/build.yml` — **нужно «да» автора.**
