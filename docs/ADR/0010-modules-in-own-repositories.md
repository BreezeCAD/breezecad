# ADR-0010: Каждый модуль — в своём репозитории

- **Status:** Proposed
- **Date:** 2026-11-08
- **Decision makers:** Михаил Афонишев (модули); сборку программы — согласовать с MikeVerx
- **Related:** [ADR-0002](0002-module-commands-and-mcp.md), [ADR-0005](0005-module-catalog.md),
  `modules/list.txt`, `scripts/fetch-modules.sh`, `scripts/modules-page.py`, `.github/workflows/build.yml`

## Контекст

Модули по правилам проекта никогда не сливаются с основой, но лежали в её
репозитории (`modules/mcp`) и собирались вместе с программой (`BZ_BUILD_MCP`).
Отсюда: общие версии и выпуски, общая сборка, нельзя держать модуль закрытым
(платные модули, Enterprise), сторонний автор модуля должен работать в чужом
репозитории.

## Решение

1. Каждый модуль — отдельный репозиторий организации: `BreezeCAD/bz-module-<id>`,
   из шаблона `BreezeCAD/bz-module-template`. Модуль собирается сам (копия
   `bz_module.h` — C ABI, без связи с библиотеками программы), тестируется без
   программы и публикует пакеты `.bzmod` для трёх систем в своих выпусках.
2. Программа модули больше не собирает. Список модулей, которые она
   предлагает, — `modules/list.txt` (по репозиторию в строке).
3. CI программы берёт пакеты своей системы из **последнего выпуска** каждого
   модуля (`scripts/fetch-modules.sh`) — дальше всё как раньше: установщик,
   артефакты `modules-<system>`, страница выпуска «modules».
4. Модуль без выпуска или без пакета для системы роняет сборку — установщик
   не теряет модуль молча.
5. Закрытые модули в `list.txt` не попадают и раздаются отдельно.

Первым перенесён MCP: `BreezeCAD/bz-module-mcp` (история сохранена).

## Последствия

- Новая версия модуля доходит до установщика и страницы «modules» со
  следующей зелёной сборкой программы, без правки её кода.
- Совместимость держится на `BZ_MODULE_ABI_VERSION` и `BZ_HAS`: меняя
  `bz_module.h`, обновить копии в репозиториях модулей (`scripts/update-sdk.sh`).
- Тест «модуль в настоящем `ModuleManager`» для MCP ушёл вместе с модулем: в его
  репозитории программа подменена; `ModuleManager` проверяется здесь на примере
  `examples/modules/hello`.

## Alternatives

- **Git submodule / subtree** — модуль снова собирается программой и
  привязан к её версиям; закрытый модуль ломает сборку открытого репозитория.
- **Оставить как есть** — не решает закрытые и сторонние модули.
