### №2 — Команда MCP с долгим пересчётом замораживает окно → ложное «BreezeCAD не отвечает»
- **Где:** 0.2.5.1-Beta, Windows; деталь ~50 операций с «Пружиной» вырезом; коды BZ-HANG-6C77CA, BZ-HANG-211777, BZ-HANG-9F49F0
- **Шаги:** 1) через MCP создать «Пружину» вырезом / снять с неё подавление / сменить переменную, от которой зависят операции после неё
- **Ожидал:** окно живое, ход пересчёта виден, ответ модулю — по окончании
- **Получилось:** окно замирает на 20–60 с; через 15 с — окно «не отвечает» с кодом ошибки, хотя пересчёт честно заканчивается. Все команды скриптинга звали `Session::RebuildNow()` — синхронно в потоке окна, без `mon::Beat()`
- **Статус:** исправлено (789539c) — в окне не проверено
- **Исправление:** коммит 789539c. Команды скриптинга зовут `scripting::Rebuild(part)` → `Session::RebuildWaiting(keepAlive)`: долгий пересчёт уходит в фоновый поток (тот же `StartBackground`, что при правке руками), команда ждёт его, прокачивая цикл окна (`Application::KeepAlive`: события, кадр, биение; ввод в документ заперт, «Recovery» не двигает точку «до команды»). Ответ модулю — по завершении, `TopologyOf` получает свежую топологию. Ход — в строке состояния (по решению: без отдельного окна): полоса «Перестроение», имя операции, «N из M», «Отменить (Esc)». Отмена: фоновый пересчёт останавливается после текущей операции, команда откатывается по истории, модулю уходит `{"ok":false,"cancelled":true}`. Модуль MCP и ABI не тронуты. · как проверено — собрано (Linux, debug), весь набор `bz_tests`; работу окна во время ожидания на этой машине проверить нечем (нет экрана) — **проверить на Windows-сборке: создать пружину через MCP на «Кубик монолит - угол 2.bzc»**

### №3 — Окно «не отвечает» не отличает долгую работу от зависания
- **Где:** 0.2.5.1-Beta, Windows
- **Шаги:** любой долгий пересчёт/экспорт в потоке окна дольше 15 с
- **Ожидал:** пока работа идёт — без кода ошибки; отчёт только при настоящем зависании
- **Получилось:** оранжевое окно, «Код ошибки», «отправьте разработчику»; «Последнее действие: command: Переменные»
- **Статус:** исправлено (789539c)
- **Исправление:** коммит 789539c. `mon::Work/WorkDone/CurrentWork` — известная долгая работа (пересчёт отмечает каждую операцию). `CrashGuard` при идущей работе ждёт вдвое дольше (30 с) и считает «тишиной» только время без биения **и** без смены операции. В отчёте — «Last action» человеческими словами («Команда модуля: part.set_variable»), «Details» (аргументы), «Working on» («Перестроение: «Пружина1», операция 27 из 52») и «No progress for»; окно показывает строку «Выполнялось: …». · как проверено — собрано; поведение сторожа на живом зависании не проверялось

### №4 — «Пружина» вырезом молча режет не всё (или ничего), статус ok
- **Где:** деталь; «Пружина» вырезом в стенку отверстия Ø22, профиль-пятиугольник с двумя вершинами ровно на R11
- **Шаги:** см. MCP-отчёт, п. 4
- **Ожидал:** канавка по всей длине или предупреждение
- **Получилось:** ok, канавки нет на большей части стенки
- **Статус:** исправлено (c43e463)
- **Исправление:** коммит c43e463. `occt::ApplyBoolean`: вырез проверяется по факту — ушёл ли материал (объём), а у протяжённых инструментов (>24 граней: пружина, резьба) ещё и по граням инструмента, которые обязаны стать стенками выреза. Неполный/пустой результат — повтор с допуском касания (`SetFuzzyValue` 1e-4, затем 1e-2, `SetNonDestructive`); не помогло — предупреждение «Вырез получился частичным: профиль касается поверхности тела — сдвиньте его на 0,01–0,05 мм». Обычные вырезы по граням не судятся (первая версия проверки ошибалась на «Канале возбуждения» и оставляла 1 270 мм³ лишнего — поймано сравнением с next и переделано). · как проверено — тест `a coil cut whose profile has corners exactly on the hole's wall cuts its groove`; на кубике тестера объём совпадает с next до 0,001 мм³ (15 265,970). Подсказка в описании feature.coil для ИИ — **не сделана** (модуль MCP не трогаю)

### №5 — Добавление с уклоном и «reversed» ничего не добавляет, статус ok
- **Где:** деталь; эскиз на YZ, выдавливание-добавление 0,5 наружу с уклоном ±45°
- **Ожидал:** материал добавлен
- **Получилось:** объём не меняется, ok
- **Статус:** исправлено (c43e463)
- **Исправление:** коммит c43e463. `LocOpe_DPrism` строит призму туда, куда смотрит поверхность эскиза, независимо от разворота грани — при «reversed» тело оказывалось по другую сторону, внутри детали. Теперь призма, построенная не в ту сторону, отражается в плоскость эскиза. Плюс добавление, которое ничего не добавило, — предупреждение «Добавление ничего не изменило…» (как у выреза мимо). · как проверено — тесты `a tapered join extruded the other way adds as much as the straight way` (0°, 10°, ±45°, оба направления) и `a join that adds nothing is a warning, not ok`

(б) `errors_now` в ответах part.set_parameter / edit_feature / set_variable — **не сделано** в этом заходе. · как проверено — весь набор тестов; на кубике тестера — предупреждения у двух операций, объём неизменен

### №7 — «Пружина» вырезом тормозит всё дерево ниже неё
- **Статус:** частично (c43e463)
- **Исправление:** коммит c43e463. Вырез больше не пересекает тело с инструментом дважды (раньше `BodiesMet` делал полное пересечение, чтобы узнать, задел ли инструмент тело, — на теле с сотнями спиральных граней это удваивало время каждого выреза после пружины): вырез идёт сразу, «задел ли» решает сам результат. Замер (тест `bench: …`, `BZ_BENCH_TURNS=28`, debug-сборка Linux): пересчёт всей детали 5,05 → 2,5–2,75 с, вырез после пружины 0,53 → 0,30–0,48 с, сама «Пружина» 4,6 → 2,3 с. Винтовая линия одним ребром и лёгкая проверка вместо `BRepCheck` — **не сделано**; отметка «тяжёлая операция» (часы + подсказка, решение принято) — **не сделана**

### №8 — Скругление не строится на рёбрах, которые обрываются о другую грань («радиус слишком большой» при любом радиусе)
- **Где:** «Кубик монолит - угол 2.bzc» (12.11.2026), паз под круглое стекло с ложем (Эскиз1 + Выдавливание1), рёбра ложа и углов паза
- **Шаги:** 1) открыть файл 2) «Сопряжение» 0,1–0,3 на дуге ложа у стенки паза или на вертикальном угле паза
- **Ожидал:** скругление
- **Получилось:** «Не удалось построить сопряжение: радиус слишком большой для этих рёбер?» при любом радиусе
- **Статус:** исправлено (c43e463), кроме двух рёбер — см. ниже
- **Исправление:** коммит c43e463. OCCT скругление строил (`IsDone`), но у конца ребра, упирающегося в стенку паза, оставлял контур грани незамкнутым на волос (BRepCheck: wire NotClosed) — программа выбрасывала результат с текстом про радиус. Теперь такой результат лечится `ShapeFix_Shape` и принимается, если объём изменился так, как требует скругление этих рёбер (сечение r²(ctg(θ/2) − (π−θ)/2) на мм каждого ребра цепочки, ±35 %); для фасок так же (треугольник). Ребро между гладко сопряжёнными гранями — честное «Ребро у точки (…) гладкое: … уберите его из выбора». Внутренний сбой OCCT на конце ребра — подсказка выбрать соседние рёбра контура (весь край паза строится там, где одно ребро не строится). На кубике тестера по 35 рёбрам переднего паза: отказов 16 → 13, а с поправленными размерами модели (№9) → 11, из которых 9 — «гладкие»/лишние линии с понятным сообщением. Не строятся отдельно: дуга ложа у задней стенки слева и угол паза вверху слева — исключение внутри OCCT (`Geom_TrimmedCurve::parameters out of range`); весь контур задней стенки при этом строится. Обе дуги ложа сразу при r = 0,3: OCCT 7.8 падает внутри (`ChFi3d_StripeEdgeInter`) — в программе это стоит одной операции (RunGuarded). · как проверено — тесты `a fillet on a seat edge that runs out into the slot's wall is built` (на старом коде падает с тем самым «радиус слишком большой») и `a fillet on an edge between faces that meet without an angle says so`; зонд по всем рёбрам паза на файле тестера

### №9 — Лишние линии на гранях: откуда берутся
- **Где:** тот же файл; линии на стенках пазов, у отверстия Ø4,2, на стенке канала Ø22, на верхней плоскости
- **Получилось / причины:**
  1. **В самой модели — почти совпадающие размеры** (программа их честно строит): окружность ложа в Эскизе1 нарисована без размера, R = 12,5645 при полуширине паза 12,56 — вылезает за стенки на 0,0045 мм и режет их почти по касательной (линии на высоте z = 14,865); «Окно переднего фильтра (вырез)» глубиной 6,15 при задней стенке паза на 6,12 (t_filtr + gubka) — ступенька 0,03 мм вокруг окна. Такие полоски видны линиями и не дают скруглить рёбра рядом.
  2. **В ядре:** `Clean()` запрещал сливать любые рёбра криволинейной грани, если она касается кривой пересечения, — разбиения одного цилиндра оставались линиями (стенка канала Ø22 у конца нарезки, отверстие Ø4,2 у Выдавливания2).
  3. Плоскости, совпадающие с точностью 1e-6, но не 1e-7 мм (накопленная погрешность рабочих плоскостей) — OCCT их не сливает.
- **Статус:** частично исправлено (c43e463)
- **Исправление:** коммит c43e463. (1) Новое предупреждение у операции, оставившей полоску тоньше 0,05 мм (узкая грань или ступенька между параллельными плоскостями), с координатами и советом «задайте одним выражением или разнесите на 0,05 мм» — виновник виден в дереве сразу, а не при скруглении. (2) `Clean()` теперь держит только кривые пересечения и рёбра у свободных поверхностей; ребро между двумя кусками одного цилиндра сливается (424 → 402 грани на кубике, объём тот же, тесты резьбы/пружины/«трубы с кольцом» проходят за прежнее время). (3) **Не исправлено:** допуск 1e-6 в `UnifySameDomain` пробовал — на кубике он менял объём детали на ~1 000 мм³ (склеивал лишнее на промежуточных шагах), откатил. · как проверено — тест `a pocket a hair deeper than the wall over it is reported where it is`; объём кубика до/после — 15 265,970 мм³
